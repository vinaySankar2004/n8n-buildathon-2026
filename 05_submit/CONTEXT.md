# Stage: Submit

## Job

Get the Devpost page and this repository submitted, complete, before the deadline.

## Inputs

`01_idea/output/pick.md`, `03_build/output/services.md`, `03_build/output/workflows/`, `04_demo/output/link.md`, `_config/rules.md`, `_config/rubric.md`, `_config/judges.md`.

## Process

1. Draft the Devpost sections so each rubric criterion has a clear home: what it does, how it was built, the problem and its size, design choices, challenges, what comes next.
2. Add the architecture diagram, three or four clean screenshots and the video link.
3. Write the disclosure section from `services.md`, every item.
4. Rewrite the README for judges and check the repository holds no keys.
5. Select the tracks the project enters.
6. Submit, then confirm the page shows as submitted.

## Audit

- [ ] A teammate reads the Devpost page cold and can say what the product does.
- [ ] Every requirement in `_config/rules.md` is met, and `checklist.md` says where.
- [ ] The repository holds no secrets.

## Output

`output/pitch.md`, the spoken pitch and answers for the judges' visit; `output/devpost.md`, the page text as submitted; and `output/checklist.md`.

Stop: submitted by Sunday 14:30. After 15:00 nobody edits Devpost or pushes here.
