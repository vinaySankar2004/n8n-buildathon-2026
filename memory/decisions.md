# Decisions

Team decisions, with date and what they affect. Add new ones at the bottom with the next number.

- **D1, 2026-11-14. Overall prizes and the n8n track only.** We do not enter the Investly finance track.
- **D2, 2026-11-14. Build the local data newsroom.** See [pick.md](../01_idea/output/pick.md).
- **D3, 2026-11-14. One n8n Cloud project, one workflow per person.** The project is LOOP newsroom. An orchestrator workflow calls each step workflow with Execute Workflow.
- **D4, 2026-11-14. Public open data, reported by neighbourhood.** A story never points at a single address, even though the city data includes addresses.
- **D5, 2026-11-14. The outlet is made up.** No real newsroom's name, logo or look.
- **D6, 2026-11-14. Storyboard before build.** We build only what the demo video shows. See [must-work.md](../02_storyboard/output/must-work.md).
- **D7, 2026-11-14. Rendering runs on a laptop behind a tunnel.** n8n Cloud cannot run local commands, so a Remotion service on Vinayak's Mac renders the video and ngrok exposes it, guarded by a token. First render through the tunnel took 5.2 seconds.
- **D8, 2026-11-14. This repository is the team workspace and the submission.** It is public from the start, so everything in it is written for anyone to read.
- **D9, 2026-11-14. The repository keeps itself in order.** Teammates never follow or learn its structure. Coding agents do the bookkeeping (see AGENTS.md), `npm run sync` pulls workflows and runs from n8n, and `tools/check.mjs` runs on every commit, push and GitHub build.
- **D10, 2026-11-14. Collect pulls 3-1-1 only.** Building permits, business licences and Statistics Canada wait until the golden path passes. "This week" is the 7 whole Vancouver days ending on the city's newest refresh. Collect keeps every request type; Score's bar does the filtering. Replaced in part by D12.
- **D11, 2026-11-14. n8n runs on Vinayak's Mac, and workflows are built as code.** The Cloud trial blocks the API, so n8n 2.47.7 (the version Cloud runs) is self-hosted beside the render service, behind one tunnel and a small router. Claude writes each workflow as JSON, deploys it, runs it and reads the result back; nobody works in the editor. Moving to Cloud later is optional: the same JSON imports there.
- **D12, 2026-11-14. The pipeline is general across Vancouver datasets.** Replaces the 3-1-1-only part of D10. Each dataset is a short config (date, category and neighbourhood fields) in the orchestrator's "Vancouver sources" node; it starts with 3-1-1, issued building permits and business licences. Score ranks every category in every source, rises and drops alike, and ignores drops to zero. Vancouver only for now. Write uses Claude through the Anthropic API, Voice ElevenLabs. An approved story is posted to a Slack outlet channel, which stands in for the outlet page. See [pipeline/README.md](../03_build/output/pipeline/README.md).
- **D13, 2026-11-14. The product is newsReels, a service.** It turns a client's own sources into short narrated news videos. Clients are newsrooms and individual content creators; each brings their input sources, and the script style is tuned to them. The rest of the pipeline stays as D12 describes. The demo client is Rain City Ledger, a made-up outlet (D5). How sources and style are set is in [proposals/vinayak.md](../product/proposals/vinayak.md) until the spec is agreed.
- **D14, 2026-11-14. The editor reviews in a Slack thread, script first.** After Write, the bot posts the headline, script, the data behind it and what goes on screen, before any voice or video is made. The editor replies in the thread in plain words; Claude revises, the number guard checks every change, and the bot posts the new draft. Approve script makes the voice and video and posts them in the same thread, where replies can still change them. Approve and publish posts to the outlet channel. Threads, not pop-up forms, so it reads as a conversation; this needs Slack event subscriptions and the router checking Slack's signature. Replaces the single approve-the-video step in D12. See [pipeline/README.md](../03_build/output/pipeline/README.md).
- **D15, 2026-11-14. Each client is one config file, and news adds context.** A client's file in `03_build/output/clients/` sets its name and look on the video, its Slack channels, its data sources, its news feeds and a style card (audience, tone, script length, words to avoid, sample scripts) that Write follows. The data still leads: 2b Context gathers recent reports, Write may add one sentence from a report on the same topic and must name it, and the guard allows a report's numbers only when the script cites that report. Rain City Ledger reads BC Government News, Environment Canada weather alerts and DriveBC road events. Review-thread edits use Claude Haiku 5.5, the low-cost model, as Vinayak asked; Write stays on Sonnet 5.5.
- **D16, 2026-11-14. Every run has a trace an editor can read.** The render service saves two pages per run: an editor trace (sources, ranking, news offered and used, Claude's instructions and answer, where each number came from, edits, approvals, tokens and cost) and a public "How this story was made" page without prompts, messages or costs. The review card links the first; the outlet post links the second. This is the pitch's answer to "you cannot see into AI".
- **D17, 2026-11-14. Anyone in the editor channel can ask newsReels for a video or an answer, and every run goes in a ledger.** "@Newsroom make a video about graffiti in Mount Pleasant" or "@Newsroom how many noise complaints this week?". 8 Request matches the ask to real categories and neighbourhoods with Claude Haiku; code builds the story and the answer from the numbers. A video opens the usual review in the request's thread. The run ledger (render service) keeps one row per run: trigger, who asked, what, status, Claude cost and ElevenLabs credits at the account's own price per credit. Data: the city has only three fresh datasets with dates, categories and neighbourhoods, so variety comes from 3-1-1's 222 request types across 22 neighbourhoods. Vinayak builds all pipeline code tonight; Arman tests from Slack.
- **D18, 2026-11-15. Editors can change the chart from the thread, and the pitch leads with local news loss.** Replies can set the chart to bar, line or pie, an accent colour and the item that stands out; after the video is made, the change remakes it (rendering is local and free, only the voice costs). Weekly charts keep their dates in order. The pitch is for hyperlocal newsrooms, neighbourhood newsletters and solo news creators, opens with 613 Canadian local outlets closed since 2008, and offers newsReels hosted or self-hosted on the client's own server for privacy.
- **D19, 2026-11-15. The Slack bot is called NewsReels.** Settles the open question in the spec. The manifest's app and bot names change, so the app needs the manifest pasted in and a reinstall. Requests are now written "@NewsReels make a video about ...". The bot spots mentions by its user ID, so no code depends on the name.
